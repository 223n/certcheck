# アーキテクチャ

certcheckの設計方針と、パッケージごとの責務をまとめます。

## 全体像

certcheckは、次の4つの内部パッケージと、それらを組み立てる`main`から
できています。

```text
main
 └─ runner ── checker
     │    └── notify
     └─ config
```

依存の向きは一方向です。`checker`と`notify`はお互いを知らず、`config`も
知りません。上位の`runner`だけが、3つを組み合わせる方法を知っています。

## パッケージの責務

| パッケージ | 責務 | 知らないこと |
| --- | --- | --- |
| `main` | 引数の解析と組み立て | 証明書の判定方法、通知の送り方 |
| `internal/config` | 設定の読み込み、検証、上書きの解決 | HTTP、Slack |
| `internal/checker` | 証明書の取得と残日数の判定 | 設定ファイル、通知先 |
| `internal/notify` | メッセージの配送 | 設定ファイル、証明書 |
| `internal/runner` | ターゲットごとの処理順序の制御 | HTTPやTLSの詳細 |

`main`は組み立てだけを担当します。どの実装を使うかを決める場所を1か所に
まとめると、実装の差し替えが`main`の変更だけで済みます。

## SOLID原則との対応

### 単一責任の原則（SRP）

変更前は、`getAPI`ひとつが「HTTPで接続する」「証明書を取り出す」
「しきい値と比較する」「メッセージを組み立てる」の4つを担っていました。

現在は、接続と判定を`checker.Check`が、メッセージの組み立てを
`checker.Result.String`が、通知するかどうかの判断を`runner`が担当します。

メッセージの文面を変えたいときに触る場所と、判定の条件を変えたいときに
触る場所が分かれています。

### 開放閉鎖の原則（OCP）

`checker.New`と`notify.NewSlack`は可変長のオプションを受け取ります。

タイムアウトや時計、時間帯を差し替えるとき、関数の呼び出し側を壊さずに
オプションを追加できます。

### リスコフの置換原則（LSP）

`notify.Notifier`の実装は、配送に失敗してもエラーを返すだけで、
プロセスを終了させません。

変更前の`postSlack`は`log.Fatal`を呼んでいたため、Slackが不調なだけで
残りのターゲットの確認が打ち切られていました。実装を差し替えても呼び出し側の
前提が崩れないよう、失敗はすべて戻り値で表します。

### インターフェース分離の原則（ISP）

`notify.Notifier`が持つメソッドは`Notify`だけです。

また、`notify`パッケージは`config.Target`を受け取りません。設定の構造を
知らずに済むよう、配送に必要な項目だけを持つ`notify.Message`を定義して
います。上書きの解決は`config.NotificationFor`が行い、`runner`が結果を
`notify.Message`へ詰め替えます。

### 依存性逆転の原則（DIP）

`runner`は、具体的な`*checker.Checker`ではなく、自分で定義した
`runner.Checker`インターフェースに依存します。

インターフェースを利用する側に置くことで、`checker`パッケージは自分が
どう使われるかを知らずに済みます。テストでは、このインターフェースを
満たすスタブを渡して、通知の判断だけを検証しています。

## テスト方針

### 二重化するもの、しないもの

HTTPやTLSは二重化せず、本物を使います。`httptest`でTLSサーバーを立て、
テスト内で発行した使い捨ての証明書を載せます。有効期限を自由に決められるため、
「あと5日」「あと100日」といった状況を正確に再現できます。

一方、`runner`のテストでは`checker`と`notify`をスタブに置き換えます。
確認したいのは通知の判断と処理の継続であり、ネットワークではないためです。

### 時刻の扱い

残日数は現在時刻に依存します。`checker.WithClock`で時計を固定し、
テストの実行日にかかわらず同じ結果になるようにしています。

### カバレッジ

```bash
go test -race -cover ./...
```

`internal`配下の4パッケージは、いずれも95パーセント以上の行を通ります。

## 変更前からのふるまいの違い

リファクタリングにあたって、次の3点はふるまいが変わっています。

| 項目 | 変更前 | 変更後 |
| --- | --- | --- |
| `http://`のエンドポイント | `resp.TLS`がnilのままpanic | エラーとして報告 |
| Slackへの通知の失敗 | `log.Fatal`でプロセス終了 | ログに出力して次へ進む |
| タイムアウト | なし（応答がなければ待ち続ける） | 10秒 |

いずれも、変更前の動作が意図したものとは考えにくいため修正しています。

メッセージの文面、判定の条件、引数、設定ファイルの形式は変えていません。
